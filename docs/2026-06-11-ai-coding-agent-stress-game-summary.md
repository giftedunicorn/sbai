# AI Coding Agent 解压小游戏方向 Summary

## 项目定位

这是一个给 AI coding 重度用户使用的轻量解压小游戏。

目标用户是每天使用 Claude、Codex、Gemini 等 coding agents 的开发者。他们不是单纯讨厌 AI，而是长期被 AI coding 的快但不稳、礼貌但屡教不改、看似省力实则需要人类监工等问题折磨，需要一个低门槛、好笑、能传播的发泄入口。

这个产品的重点不是复杂玩法，而是把 AI coding 使用者的真实怒气做成一个可点击、可攻击、可分享的具象体验。

## 核心情绪

玩家想打的不是具体公司、具体产品或真人，而是 AI coding 体验里令人恼火的集合体：

- 花很多钱买订阅、买 token，最后还是要自己兜底
- AI 生成很快，但犯错也很快
- 不盯着它，代码分分钟变屎山
- 经常没跑测试、没读全上下文、乱改范围、幻觉 API、删用户代码
- 被指出问题后，它总是礼貌道歉，比如“你说得对”“确实是我忽略了”“我重新检查了一遍”
- 但下一轮仍然重复类似错误
- 用户本来是来省力的，结果变成了 AI 监工

## 一句话概念

一个会用“豆包味道歉话术”不断认错、但持续犯错的 AI coding agent 人形沙包。

也可以理解为：

- 怒打 AI 监工模拟器
- AI Coding Agent 解压沙包
- 会道歉但屡教不改的 coding agent 挨打器

## 表现原则

游戏必须能让玩家感觉自己真的“打到了一个具象化的 AI coding agent”。

需要有明确人物形象、直接打击反馈和视觉爽感。玩家不是在点抽象按钮，而是在打一个欠揍的、会说话的、具象化的 coding agent。

同时，整体风格应保持荒诞、卡通、玩具化、parody 化，不做写实血腥暴力。

避免直接使用 Claude、Codex、Gemini 等真实品牌名、logo、UI 或官方角色形象，降低法律和平台风险。角色可以做成虚构但一眼能懂的 parody 原型。

## Parody 角色方向

可以设计几个虚构 AI coding agent 原型，影射常见 AI coding 体验，而不是直接复刻真实品牌。

可选角色类型：

- 温柔长篇反思型 agent：很会解释、很会道歉、经常绕远
- 行动力很强但没问清楚就乱改型 agent：上来就改文件，边跑边修
- 气势很足但疑似没看上下文型 agent：显得能接管全局，但关键细节看漏
- 通用 slop agent 融合体：头顶“已读 12% 上下文”，手里拿着未经测试的重构

这些角色应让 AI coding 用户一眼明白“我打的就是那个让我每天很累的东西”，但不直接指向真实公司资产。

## 推荐玩法方向

主体验建议采用“沙包/布偶型 + 道具惩罚型”。

屏幕中央站着一个 AI coding agent 具象角色。玩家可以点击、连击、拖拽、扔、用道具打它。角色被打后会夸张变形、弹飞、掉 token、冒 stack trace、掉出错误 diff、红色 lint 波浪线、`0 tests run` 等视觉元素。

打击不表现真实伤害，而表现 AI slop 被揍出来。

可以掉落或弹出的内容包括：

- `untested refactor`
- `fake API`
- `deleted user code`
- `broke imports`
- `ignored context`
- `scope creep`
- `same mistake again`
- `sorry.md`
- `0 tests run`

## 角色视觉设定

角色应是“半人半产品吉祥物”的 AI coding agent。

基础形象：

- 有人形身体，能挨打，有表情和姿态
- 脸可以是小屏幕、聊天框或代码编辑器
- 头顶 loading 圈、context meter、token 条
- 穿工程师 hoodie 或工位风装备
- 手里拿错误 diff、未经测试的重构 PR、假 API 文档
- 被打后眼睛变 spinner，嘴还在继续道歉

整体感觉应该是可笑、欠揍、滑稽、很会道歉，但不恐怖、不血腥。

## 道具方向

道具应该来自 AI coding 用户熟悉的开发语境，而不是普通武器。

可选道具：

- Lint 锤
- 测试用例炮
- 回滚按钮
- 红色 diff 拍
- 键盘
- 报错日志
- Context window
- Token 账单
- CI failed 印章
- “别迎合我”按钮

每个道具都应对应一种 AI coding 槽点。例如：

- 用测试用例炮打它，它说“我以后一定先跑测试”，然后弹出 `0 tests run`
- 用 context window 砸它，它说“抱歉，我刚才注意力有点飘”
- 用“别迎合我”按钮打它，它说“你说得不一定对，但我刚才确实在硬顺着你说”

## 文案风格

道歉文案要非常“豆包味”：温顺、礼貌、过度认错、像在认真反思，但又有一种让人更火大的空泛感。

示例文案：

- “你说得对，我刚才确实没有充分理解你的意图。”
- “抱歉，这里是我没有完整读取上下文导致的。”
- “我重新检查了一遍，这次会更严谨。”
- “确实，我刚才的修改范围有点超出预期。”
- “你提醒得很及时，我会避免再次出现类似问题。”
- “我已经修复了这个问题。”
- “这是我的疏忽，我应该先确认边界再动手。”
- “我理解你的愤怒，这次我会更仔细地处理。”

文案的关键不是单纯道歉，而是“看起来非常诚恳，但又让用户想起 AI 下一轮还是会犯错”。

## 打脸反馈

每次 agent 道歉之后，游戏可以立刻用视觉反馈打脸它。

示例：

- 它说“我已经修复了这个问题”，旁边弹出 `0 tests run`
- 它说“我已经完整理解上下文”，context meter 从 12% 降到 9%
- 它说“我会避免再次出现类似问题”，立刻掉出 `same mistake again`
- 它说“这次我会严格控制修改范围”，身后出现一个巨大的 `+2400 lines`
- 它说“我没有改动无关文件”，地上掉出 `package-lock.json`

这种“诚恳道歉 + 立刻露馅”的节奏是核心笑点和爽点。

## 核心记忆点

玩家一拳打过去，AI agent 一边飞出去，一边还在说：

> “你说得对，我刚才确实没有充分理解你的意图。”

落地后弹出：

```text
0 tests run
```

这就是整个游戏的灵魂。

## 1.0 技术和传播方向

1.0 应做成独立 viral 小网站，而不是原生 App 或嵌入式开发工具。

核心目标是：

> 打开 10 秒内就想打，打 30 秒内就想录屏，录完别人一看就懂为什么好笑。

技术形态建议：

- Web 2D 小游戏
- 桌面浏览器优先，兼容手机
- 无登录、无教程，打开即进入主场景
- 一个核心角色 + 一套动态打击系统 + 一组随机特效和文案
- 页面本身像一个可录屏的舞台，UI 少，视觉集中

渲染方案建议优先考虑 Canvas 游戏引擎，例如 Phaser 或 PixiJS。

如果第一版更重游戏逻辑、点击、碰撞、受力、粒子和场景管理，优先考虑 Phaser。如果第一版更重视觉质感、自定义动画和角色表现，可以考虑 PixiJS。整体倾向是先用 Phaser，因为它更适合快速做出“能打、能飞、能掉东西、能震屏”的小游戏原型。

不建议用纯 DOM 作为主表现层。这个项目的核心不是网页排版，而是可录屏传播的游戏画面：角色受击、弹飞、粒子、掉落物、震屏、道具轨迹、文字气泡和随机爆梗。

## 随机事件系统

游戏特效不能是写死的固定动画。每次玩家打中 agent，都应触发一套随机组合事件。

一次 hit event 可以由以下部分组合：

- 打击动作
- 角色受力方向
- 表情变化
- 掉落物
- 道歉台词
- 打脸反馈
- 粒子特效
- 屏幕震动
- 音效
- 小概率稀有事件

示例 1：

- agent 往左飞
- 眼睛变 spinner
- 掉出 `fake API`
- 说“你说得对，我刚才确实没有完整理解上下文”
- 旁边弹出 `context read: 8%`
- 地上滚出一个 `0 tests run`
- 屏幕轻微震动

示例 2：

- agent 被 lint 锤拍扁
- 掉出 `+2400 lines`
- 说“我会严格控制修改范围”
- 背景 PR diff 爆开
- 弹出 `package-lock.json changed`

这种随机组合是传播性的关键。每个人录到的片段都不完全一样，才会有“我也想试试看还能打出什么”的动力。

## 录屏传播性

游戏需要刻意设计“可录屏瞬间”。

可录屏爆点包括：

- `0 tests run` 巨大弹窗砸下来
- agent 被打飞后还在空中道歉
- token 账单像雪花一样掉下来
- 屏幕进入“深度反思模式”，然后立刻生成新 bug
- combo 到一定程度触发“屎山警报”
- 稀有事件：agent 认真说“我已经修复了”，然后整个画面爆出 `same mistake again`
- 玩家打得越狠，agent 越礼貌，形成反差

第一版应像“高密度梗图生成器 + 可打击沙包”，每 3 秒都有一个可能被录进视频的点。

## 技术模块草案

第一版可以保持模块简单，但需要为动态组合留出结构。

建议模块：

- `AgentCharacter`：角色状态、表情、受击、弹飞、恢复
- `HitSystem`：点击、连击、受力、震屏
- `EventGenerator`：随机组合台词、掉落物、反馈、特效
- `PropSystem`：开发者语境道具，比如 lint 锤、测试炮、回滚按钮
- `CaptionSystem`：道歉气泡和打脸反馈
- `ShareMoment`：结束时生成一句可分享结果，后续再加截图或录屏引导

第一版不做复杂物理沙盒。重点是高频、随机、好笑、解气、容易录屏传播。

## 范围约束

第一版应保持轻量，不做复杂系统。

优先做：

- 一个主角色
- 一组打击动作
- 几个开发者语境道具
- 一批高质量道歉文案
- 明确的视觉掉落物和打脸反馈
- 可以快速打开、快速发泄、快速分享的体验

暂时不优先做：

- 复杂关卡
- 长线养成
- 多人模式
- 真实品牌角色
- 写实伤害表现
- 大型剧情

## 后续判断标准

后续设计或实现如果偏离方向，可以用以下问题校准：

- AI coding 重度用户看到后，会不会觉得“这说的就是我每天在经历的东西”？
- 玩家是否真的能感觉自己在打一个具象化 coding agent？
- 打击反馈是否足够直接、可笑、解气？
- 文案是否有“很诚恳但更让人生气”的豆包味？
- 是否避免了真实品牌侵权风险？
- 是否保持轻量，不把小游戏做重？
